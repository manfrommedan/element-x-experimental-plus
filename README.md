# Element X+

**Element X, только лучше.**

[![база](https://img.shields.io/badge/база-Element%20X%20v26.07.1-1c7c6f)](https://github.com/element-hq/element-x-android)
[![лицензия](https://img.shields.io/badge/лицензия-AGPL--3.0--only-blue)](LICENSE)
[![сборки](https://img.shields.io/badge/сборки-GitHub%20Releases-24292f)](https://github.com/manfrommedan/element-x-experimental-plus/releases)

Экспериментальный форк [element-hq/element-x-android](https://github.com/element-hq/element-x-android):
повседневный UX подтягиваем до уровня WhatsApp, Telegram и Signal,
протокол и шифрование не трогаем.

</div>

> [!WARNING]
> **Неофициальный форк.** Не связан с Element Hq Ltd. и командой Element Call,
> не одобрен ими и с ними не координируется. Работает как есть, на свой страх
> и риск, без гарантий и SLA. Issue по здешним правкам в апстримном репозитории
> не открывайте.

## Установка

APK лежат в [релизах](https://github.com/manfrommedan/element-x-experimental-plus/releases),
отдельно под каждую ABI и universal. Ставится **рядом** с официальным клиентом:
`applicationId` = `io.element.android.x.plusng`, имя приложения Element X+.

> [!NOTE]
> Package id менялся с `.plus` на `.plusng`, поэтому обновиться поверх старого
> билда нельзя. Если стоял прежний Element X+, удалите его перед установкой.

## Что меняется

| | Element X | Element X+ |
|---|---|---|
| **Голосовой звонок** | сетка участников Element Call, лобби перед входом | телефонный вид: аватар, таймер, четыре кнопки; звонок из шапки любой комнаты в один тап |
| **Входящий** | тихое heads-up уведомление | полный экран с рингтоном, ответ с локскрина, видео можно принять без камеры |
| **Групповой голосовой** | инициатор слышит тишину, у получателей беззвучный баннер | звонит как личный |
| **Пачка фото** | по сообщению на файл | одно галерея-событие по MSC4274, коллаж видят и другие клиенты |
| **Выделение** | одно сообщение за раз | до 30 разом: копировать, переслать, удалить |
| **Загрузка вложения** | ждём и не отменяем | прогресс и крестик прямо на плитке |
| **Навигация по истории** | только скролл | тап по плавающей дате прыгает к началу дня, с дозагрузкой |
| **Удалённые сообщения** | плашка на каждое | схлопываются в один блок с авторами |
| **Ссылки** | голый текст | карточка предпросмотра через ваш homeserver, IP на сторонний сайт не утекает |
| **Избранное** | в общей куче | своя секция сверху |
| **Сеть под DPI** | нужен внешний VPN | встроенный обфусцированный транспорт до своего сервера |

<details>
<summary><b>Подробно: сообщения и медиа</b></summary>

**Множественный выбор.** Долгий тап включает выбор, дальше копирование,
пересылка и удаление до 30 сообщений за раз. На медиа долгий тап открывает
обычное меню, где есть пункт «Выбрать». Системные события и удалённые
сообщения в выбор не попадают, выбор переживает поворот экрана
(апстрим-issue #6737).

**Отправка пачки.** Ведёт апстримовский флаг, батч уходит одним событием.
От форка здесь экран превью: лента миниатюр, добавление на лету с отсечкой
дублей, сжатие настраивается на каждый элемент отдельно, подпись одна на весь
блок, прогресс по фазам. Цена та же, что у любой галереи: это одно сообщение,
отдельную картинку из набора не удалить и не переслать.

**Предпросмотр ссылок.** Карточку отдаёт homeserver, картинки идут через него
же. Матрикс-пермалинки и упоминания не превьюятся. В зашифрованных комнатах
запрос не уходит, пока не выберете «всегда».

</details>

<details>
<summary><b>Подробно: звонки</b></summary>

Гудки синтезируются через Web Audio и обрываются точно в момент ответа, а не
после регистрации участника в LiveKit. Пока идёт дозвон, вместо пустого места
под аватаром показывается «Соединение…».

Аудио доведено до поведения обычной звонилки: VoIP-фокус запрашивается явно
(иначе на Pixel и AOSP входящий из уведомления оставался беззвучным), фокус
берётся как `GAIN_TRANSIENT`, поэтому музыка после звонка возобновляется сама,
голос идёт в ушной динамик, а не в громкую связь, громкость поднимается до
слышимого минимума если пользователь увёл её в ноль.

На телефонах без Google Services (Huawei, WebView на Chromium 114) добавлены
полифил `Promise.withResolvers` и запасной CSS Grid, без них экран звонка
оставался белым.

Полный разбор по пунктам: [EXPERIMENTS.ru.md](phone-layer/docs/EXPERIMENTS.ru.md).

</details>

<details>
<summary><b>Подробно: антицензурный прокси</b></summary>

Поддержка self-hosted [mxtr-proxy](https://github.com/manfrommedan/mxtr-proxy).
Маскирует трафик матрикс-клиента под обычный TLS, помогает обходить DPI и
блокировки типа ТСПУ, когда штатный путь до homeserver или Element Call SFU
обрезан. Поднимается на своём VPS, подключается через share-string, локальный
порт назначает система. При выключении сразу идёт прямой коннект.

100% гарантий нет: DPI-движки развиваются, любая маскировка не вечная,
регуляторные риски остаются на стороне пользователя. Но это большой шаг в
сторону свободного общения там, где прямой коннект больше не работает.
Свободу нельзя ждать от вендоров, её берут руками.

</details>

<details>
<summary><b>Что пробовали и убрали</b></summary>

| Что | Почему |
|---|---|
| Свайп-выделение диапазона | слишком легко срабатывало при обычной прокрутке |
| Встроенный плеер YouTube в ленте | WebView на каждое сообщение дороже пользы, ссылка открывается в приложении |
| Сборка коллажа на стороне клиента | заменена галерея-событием, которое видят и другие клиенты |

| Очистка кэша комнаты | Rust SDK 26.06.x убрал `clearEventCacheStorage`, вызывать стало нечего |
| Ярлык звонка в списке чатов | реализация на месте, но выключена и скрыта, пока не починим |

</details>

<details>
<summary><b>Что починено против апстрима</b></summary>

* Живая геопозиция не будит foreground-сервис после убийства процесса и не ест
  батарею, когда ей ни разу не пользовались.
* Несколько видео из превью вложений отправляются, а не теряются после первого.
* Начатое редактирование сообщения переживает прикрепление медиа.
* Экран звонка закрывается когда падает render-процесс WebView, вместо пустой
  страницы и утянутого следом приложения.
* Массовая пересылка сохраняет хронологический порядок.
* Разделители дней не остаются сиротами после скрытия удалённых сообщений.
* Возврат из шаринга одной кнопкой Назад приводит в вызвавшее приложение.

</details>

## Сборка

```bash
./gradlew :app:assembleFdroidPlusRelease -PdisableR8 --no-daemon
```

`-PdisableR8` нужен на хостах меньше примерно 16 ГБ ОЗУ, иначе R8 уходит в OOM.
Патченый Element Call закоммичен как
`features/call/impl/libs/element-call-embedded-plus.aar`, собирать его отдельно
для рутинной сборки APK не нужно.

Флейворы: `store` (`gplay` / `fdroid`) × `fork` (`vanilla` / `plus`). Форковые
фишки живут в `plus`, `vanilla` остаётся апстримовским.

APK собирает GitHub Actions по ручному запуску, а не на каждый push: ветка
живёт быстро, релиз на коммит никому не нужен. Workflow держит три последних
релиза и подчищает старые прогоны.

## Зачем это всё

Element X силён протоколом и шифрованием, но по повседневным мелочам заметно
уступает мессенджерам, с которыми его сравнивают. Команда апстрима двигается
осторожно, ревью долгое, и многие приятные вещи остаются за бортом.

Форк это полигон: проверяем решения на живом юзкейсе, не дожидаясь официального
трека, в надежде что мейнстрим со временем заберёт их к себе. Часть правок уже
уехала в апстрим пул-реквестами.
